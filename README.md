# 开干角 · 本地待办与桌面设置

本地 Windows Forms 待办程序，无联网、遥测、账户、提醒、日历或云服务。

## 运行

从 GitHub Releases 下载 `KaiGanJiao-v1.0-win-x64.zip`，解压后双击 `KaiGanJiao.exe`。这是免安装的便携版，已包含 .NET 10 运行组件，适用于 Windows x64。可以把 EXE 创建为桌面快捷方式。程序未签名，首次运行时 Windows 可能提示确认。

源码构建：需要 .NET 10 SDK。旧的 `开干角-MVP` 发布目录仍依赖本机 .NET 10 Desktop Runtime（x64）；不要只移动其中的 EXE。

- 右上角 `+` 新增；默认「这周拿下」。Enter 保存，Esc 取消。
- 双击任务文字编辑；右键可编辑、移动模块、删除。
- 左侧圆圈打开完成确认。默认焦点在「等等，好像还差一点」；直接按 Enter 或 Esc 都取消。选择「是的，我已经全部完成了」后隐藏任务。
- 任务较长时换行并截断，悬停查看全文，也可双击进入编辑框查看。
- 天数从创建 UTC 时间按满 24 小时累计，移动和编辑不重置。
- 拖动系统标题栏移动窗口，拖动边缘调整大小。默认关闭窗口会退出，数据保留。

## 设置与桌面行为

右上角 `···` → **设置…**，修改后点保存，取消或 Esc 不生效。三个新开关默认关闭，旧设置文件自动兼容。

- **贴边自动隐藏**：把窗口拖到屏幕上、左或右侧外边缘并松手，鼠标离开约半秒后收起为蓝色细条；鼠标移入细条即可展开。正在编辑或操作菜单时不会收起。拖离边缘可解除停靠；关闭此开关会立即恢复窗口。为避免窗口跑到相邻显示器上，两个显示器的接缝不触发隐藏；任务栏占用的边缘和下边缘也不触发。没有隐藏动画或高频指针轮询。
- **关闭窗口后后台常驻（隐藏到托盘）**：开启时点 × 只隐藏；双击托盘图标或右键选择“显示窗口”可恢复。关闭时点 × 彻底退出，不再占用运行资源。托盘菜单和主窗口更多菜单中的“退出程序”始终彻底退出。Windows 关机或注销不会被常驻开关阻止。
- **开机自启动**：开启后在当前用户登录 Windows 时启动，不需要管理员权限；关闭后删除本程序的启动项。使用 [Windows 当前用户 Run 启动项](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)，只操作名为 `KaiGanJiao` 的值。若在 Windows 任务管理器或“启动应用”里另行禁用，需要在那里重新开启；换路径后应重新保存自启动设置。
- **新增任务的默认模块**：可选择四个模块之一。

开启贴边隐藏或后台常驻时会显示托盘图标。窗口隐藏后再次双击 EXE 会唤回已有窗口，不重复运行。托盘图标可能位于任务栏的隐藏图标区域。

隐藏窗口时暂停界面的天数计时；再次显示会按 UTC 重新计算。后台常驻仍会保留程序内存，“后台常驻”开关不是内存限额或资源监测开关。

## 本地数据与恢复

程序使用 `%LOCALAPPDATA%\KaiGanJiao` 保存数据，设置面板中的“打开数据文件夹”按钮可打开实际保存目录。如果从 MSIX 打包的宿主程序启动，Windows 可能把 AppData 重定向到宿主的 `LocalCache` 下；按钮会通过 Windows 目录句柄解析真实位置后再打开，避免资源管理器提示“位置不可用”。不会为修复打开目录而移动、复制或重置任务。备份时以该按钮打开的实际目录为准。

- `tasks.json`：未完成和已完成任务。完成与删除是独立操作；已完成任务保留在数据中，不提供历史页面。
- `settings.json`：独立保存默认模块及贴边隐藏、后台常驻和开机自启动设置。
- `*.bak`：上一版自动备份；首次保存也生成备份。每次操作先写临时文件并落盘，再替换主文件。
- 主文件无法解析或不满足数据格式时尝试备份；损坏原文件保留为 `*.damaged-*` 并提示恢复情况。恢复上一版可能缺少最后一次修改。
- 主文件和备份均异常时停止加载，避免用空列表覆盖原内容。访问权限、磁盘问题会报错，不默默重置。
- 手动备份：退出程序后复制整个数据目录到自己选择的位置。恢复：先另存当前整个目录，再把需要的备份复制为 `tasks.json`（或 `settings.json`），重新启动。
- 发布目录和数据目录分离，更新程序不触碰用户数据。命名事件用于重复启动时唤回已有窗口，数据写入锁防止 JSON 被两个写入者覆盖。

## 开发

环境：Windows 11 x64，系统版本 10.0.26200；SDK 10.0.201，MSBuild 18.3，桌面运行时 10.0.5。使用 .NET 10，Windows 11 兼容范围见 [Microsoft 官方支持表](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)。

```powershell
dotnet build KaiGanJiao.sln -c Release
dotnet run --project tests/KaiGanJiao.Tests -c Release
dotnet run --project src/KaiGanJiao.App
```

- `src/KaiGanJiao.Core`：稳定模块 ID、不可变任务、UTC 天数算法、任务服务、JSON 原子保存。
- `src/KaiGanJiao.App`：WinForms 主窗口、编辑/确认面板、按下一天数边界计时、休眠恢复与系统时间变化事件。
- `tests/KaiGanJiao.Tests`：无需第三方测试包的自动化测试可执行程序；断言失败以非零退出码报告。测试数据单独保存在 `artifacts/tests`。
- 可使用 `KaiGanJiao.exe --data-dir "绝对测试路径"` 启动隔离测试实例。
- 隔离实例禁止修改正式 Windows 启动项。`dotnet run --project tests/KaiGanJiao.Tests -c Release -- --desktop` 可仅运行新增桌面功能测试。启动项测试使用模拟注册服务，验证开启、关闭、保存失败回滚和权限错误；尚未实际注销或重启 Windows 验证登录自启。

没有每秒轮询，没有常驻网络线程；没有待办时不启动天数定时器。本阶段不声明具体内存或 CPU 数值。

## 真实桌面验收步骤

自动化已覆盖核心操作、时间边界及窗口定时器自动更新、重启读取、文件锁定时写入失败、备份恢复、损坏保护、Enter 保存、Esc 取消、确认按钮和取消焦点，以及多任务滚动布局。实际桌面已检查主窗口和面板布局，并完成新增、取消完成、确认完成后隐藏及落盘验证。桌面自动化工具对模态面板键盘输入的焦点处理不稳定，快捷键验证来自控件消息处理自动化测试。以下硬件及长期行为仍需真实环境验证，不等同于编译或模拟测试已通过：

1. 在 100%、125%、150%、200% 缩放显示器之间拖动主窗口，打开编辑和确认面板，检查标题、副标题、按钮及长任务是否裁切。程序启用 PerMonitorV2；不要为测试修改正式待办数据。
2. 在不同位置和尺寸的显示器间拖动及缩放窗口，确认可操作与滚动。本阶段不记忆窗口位置。
3. 在隔离测试目录中新建任务，退出后把该测试任务 `createdUtc` 调整到当前 UTC 前 23 小时 59 分，再启动，跨过一分钟后确认自动从 0 天变为 1 天。不得修改正式数据来做测试。
4. 使用同样的临界测试数据，在临界前让电脑休眠，过边界后唤醒，确认数字立即重新计算。
5. 连续使用 8–24 小时，反复新增、编辑、完成和滚动，观察工作集、私有内存及进程 CPU 时间；第三阶段正式记录测试环境、任务数、采样区间和测量结果。

新增桌面验收：分别在上、左、右外边缘拖放，移开鼠标后检查收起，再移入细条展开；打开编辑框时不得收起；开启后台常驻后点 ×，从托盘或再次启动 EXE 恢复，最后用菜单退出；关闭常驻后点 × 应直接退出。开启自启动后，在方便时注销或重启电脑，确认登录后自动打开，再关闭该开关确认不再启动。多显示器接缝已做几何模拟测试，真实混合 DPI 多屏和显示器热插拔仍需手工验收。

仍未实现：无边框、圆角定制、透明度、始终置顶及窗口位置/大小记忆。长时间资源测量仍待后续阶段。
